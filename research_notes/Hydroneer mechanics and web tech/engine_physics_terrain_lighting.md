## 1. Engine, version, physics backend, physics quirks and mitigations

### Takeaway
Hydroneer shipped on **Unreal Engine 4.26 with PhysX 3** (CL-15973114) and was still on 4.26/PhysX as of the May 2026 optimization build. It never moved to UE5 or Chaos. The game's main physics trick: loose items become dynamic rigid bodies only while they are moving. Once they settle they are "locked" (simulation off). That, plus clear/no-save options for loose dirt and ore, plus purely kinematic conveyors, is how the devs keep thousands of objects workable.

**Physics project settings** (from the cooked DefaultEngine.ini shipped in the RFC modkit; it includes game-specific custom collision channels, so it appears copied from the game) [DATAMINE, moderate confidence] — [RFC template Mining/Config/DefaultEngine.ini](https://github.com/RFC-MiningCompany/HydroneerTemplate):
- `DefaultGravityZ=-980` (standard 9.8 m/s² in cm).
- `bSubstepping=True`, `bSubsteppingAsync=True`, `MaxSubstepDeltaTime=0.008333` (120 Hz substeps), `MaxSubsteps=6`, `MaxPhysicsDeltaTime=0.033333`.
- `bEnablePCM=True`, `bEnableStabilization=False`, `bDisableCCD=False`, `bEnableEnhancedDeterminism=False`.
- `SmoothedFrameRateRange` 22–200.
- Custom collision channels: `Water` (trace), `VehicleSuspension` (trace), `Zone`, `Grounded`, `Moving`, `Held`, `StoredNoClip`, `StoredClip`, `Placing`, `Magnet`, `Conveyored`, `HydroLandscape`, `NoClip`. These show that an item's collision response is swapped by *state*: held, stored in a container, being placed, on a conveyor, magnetised, and so on.

**How item physics is managed (the base item class `BP_ParentItem_C`)** [DATAMINE, 2022 SDK] — [RFC SDK BP_ParentItem_Classes.h](https://github.com/RFC-MiningCompany/HydroneerTemplate):
- Functions `TriggerPhysics`, `TriggerPhysicsKeepReact`, `LockPhysics`, `PhysicsLockTimer` and `OverrideLockedPhysics`, plus `Set_Item_Physical_Reactions(E_PhyReact)` and `SetMeshPhysicalReaction` (an 8-value enum of physics "reaction" modes). Also `SetAllResponseToChannel`, `CanChangeMeshCollisions_`, `Scan_for_Items_on_Top` and `ScanForDropCollision(bool* Can_Drop_)`.
- `ProxyItem`/`CreateProxy_`/`ProxyOffset`/`ToggleOnlyOwnerSee` mean a held item is shown as a separate proxy mesh.
- Resources (`BP_ParentResource_C`) add `Weight` (SaveGame float), `BaseValue`, `ConveyorsColliding`, `DoNotClear`, and `SetResourceSize` (size scales with weight).
- Measured at runtime (2026 build, UE4SS): in a new world with 557 items and about 8,000 mesh components, **zero bodies were simulating physics at rest**, checked at 20 s and 50 s. "The game already turns off physics for everything that is stopped" [DATAMINE/measurement] — [Mp_hydroneer docs/07-spike.md](https://github.com/ericksouza95/Mp_hydroneer/blob/main/docs/07-spike.md). This cross-checks the `LockPhysics` / `PhysicsLockTimer` names in the 2022 SDK.

### Inferences
- [INFERENCE] The core pattern for a browser clone: items are dynamic only while disturbed (dropped, thrown, hit), then frozen into static or kinematic bodies after a settle timer. Neighbours stacked on top (`Scan_for_Items_on_Top`) get re-awakened when a support is removed. Sleeping with forced freezing scales far better than relying on the engine's own sleep thresholds.
- [INFERENCE] Collision state machines (held, stored, conveyored, placing) remove most item-versus-item interactions, which are the source of jitter and "explosions". A stored item is effectively a non-colliding attached child.
- [INFERENCE] The 120 Hz substepping with 6 max substeps is a stability measure for small, fast objects such as ore and dirt chunks.

### Gaps
- No explicit dev statement names "PhysX" (the PhysX evidence is the binary scan). No hard cap on item count was found. The 8 `E_PhyReact` enum values are unnamed in the dump (`NewEnumerator0..8`), so their exact meanings (e.g. none, physics, locked, kinematic) are unknown.
- The PCGamingWiki and SteamDB pages returned 403, so their settings tables were not checked.

## 2. Diggable terrain: technology, saving, depth limits, tools

### Takeaway
The terrain is **Voxel Plugin (Pro) by Phyronnaz**, i.e. smooth (marching-cubes-style) voxel volumes rather than heightmaps. Each dig site is a voxel world actor (`BP_HydroVoxelWorld_C : AVoxelWorld`). Its edits are stored as a compressed voxel save inside the game save. Dig sites are deliberately few and bounded because of "harsh technical limitations", and dirt *tier* is a function of depth (Z).

### Cited Findings
- Official presskit: "state-of-the-art voxel based terrain system" for "cave networks, quarry pits, and mud mountains"; the site shows a Voxel Plugin logo [DEV] — [hydroneer.com](https://hydroneer.com).
- The 2.0 patch notes say "Voxel plugin update. Performance improvements and much smoother voxels!" [DEV] — [2.0 notes](https://store.steampowered.com/news/app/1106840/view/4348799082201741462).
- **Pro vs Free**: the shipped plugin is **VoxelPro**, and the binary contains `VoxelMultiplayerTcpInterface` (a Pro-only feature) [DATAMINE] — [Mp_hydroneer 01-pesquisa](https://github.com/ericksouza95/Mp_hydroneer/blob/main/docs/01-pesquisa.md); [Buckminsterfullerene template Plugins/VoxelPro](https://github.com/Buckminsterfullerene02/Hydroneer-Template). The RFC modkit substitutes "VoxelFree" so modders without a Pro licence can compile — [RFC Mining.uproject](https://github.com/RFC-MiningCompany/HydroneerTemplate). The Voxel Plugin docs describe the TCP multiplayer as "Pro only" and say it "won't work on Steam" — [Voxel Plugin docs 1.2: Multiplayer](https://docs.voxelplugin.com/1.2/core-systems/voxelworld/multiplayer). Modules in the 2022 dump: `Voxel`, `VoxelGraph`, `VoxelFoliage`, `VoxelHelpers`, `VoxelNiagara`, `VoxelExamples` [DATAMINE].
- `BP_HydroVoxelWorld_C : AVoxelWorld` has fields `TOPSOIL` (scene component), `IsHorizontal_` (the Icehelm "horizontal dig site"), `CompressedSave` (`FVoxelCompressedWorldSave`, SaveGame), `BeenEdited_` (SaveGame) and `AmountSaved`. A separate `BP_VoxelNoDig_C : AVoxelWorld` is a non-diggable voxel world [DATAMINE] — [RFC SDK BP_HydroVoxelWorld_Classes.h / BP_VoxelNoDig_Classes.h](https://github.com/RFC-MiningCompany/HydroneerTemplate). The 2.0 notes also mention the "Icehelm horizontal dig site. Like normal dig sites, the deeper you go the better the resources" [DEV] — [2.0 notes](https://store.steampowered.com/news/app/1106840/view/4348799082201741462).
- Edit API used: `VoxelSphereTools` — `AddSphere`, `RemoveSphere`, `SetValueSphere`, `RemoveSphereWithDurability` plus Async variants. The co-op mod hooks these on the host to capture and replay terrain edits [DATAMINE] — [Mp_hydroneer 01-pesquisa](https://github.com/ericksouza95/Mp_hydroneer/blob/main/docs/01-pesquisa.md); [hydroneer-coopnet README](https://github.com/Zane11332/hydroneer-coopnet) ("the host's exact terrain edits are repeated on the friend's side").
- Player controller functions include `MoveDirt(bool PickUp, float Radius)`, `RemoveDirtByLocation(Location, Radius)` and `LevelTerrain(FVoxelIntBox Remove, FVoxelIntBox Add)` (the latter for the rake / levelling) [DATAMINE] — [RFC SDK BP_GameController_Classes.h](https://github.com/RFC-MiningCompany/HydroneerTemplate); [Mp_hydroneer 07-spike](https://github.com/ericksouza95/Mp_hydroneer/blob/main/docs/07-spike.md).
- Voxel collision streaming: the player character derives from `AVoxelCharacter` and carries a `UVoxelSimpleInvokerComponent`. **Drills also carry a `VoxelSimpleInvoker`** [DATAMINE] — [RFC SDK BP_GameCharacter / BP_ParentDrill](https://github.com/RFC-MiningCompany/HydroneerTemplate). Voxel Plugin docs: collisions are generated "only where needed" near invokers. "It's not possible to enable high quality navmesh & collisions on the entire world" — [Voxel Plugin docs: Collisions & Navmesh](https://docs.voxelplugin.com/1.2/core-systems/voxelworld/collisions-and-navmesh). Matching dev fix in 2.0.6: "Moving far away from a dig site will no longer fudge collisions while machinery is running" [DEV] — [2.0.6 notes](https://store.steampowered.com/news/app/1106840/view/4474904295773706248).
- Few dig sites, by design: "We have to be careful about how many and how large these dig sites can be, as there's some pretty harsh technical limitations… with the technical side of terrain digging. From our research… players tend to only use a maximum of 3 dig sites, so we feel that 6 is enough" (Volcalidus) [DEV] — [Dev vlog 24 Mar 2024](https://store.steampowered.com/news/app/1106840/view/5686430301729334870).
- Terrain artifacts fixed: "Removed issue with tears appearing in diggable terrain" (3.0) — [MEGA PATCH](https://store.steampowered.com/news/app/1106840/view/5756237364312335366). "Greatly decreased the chance that tiny specs of dirt will appear when digging" (2.1, i.e. floating voxel fragments) — [Steam Farming Season](https://store.steampowered.com/news/app/1106840/view/4980448574112987724).

### Inferences
- [INFERENCE] `BeenEdited_` suggests untouched dig sites skip saving and regenerate procedurally from the voxel generator. Only edited worlds store a compressed blob. For a browser clone, store edit diffs per chunk, or run-length-encode chunk data only for dirty chunks.

- [INFERENCE] Equivalent tech for the web: chunked SDF (signed-distance) voxels with marching cubes or surface nets, sphere add/remove brushes, a hard bedrock floor, and depth bands driving both material and texture.

## 3. Dirt and material physics; water and dirt interaction

### Takeaway
Dug dirt exists in three forms:
- **Voxel volume**, in the terrain.
- **An abstract "load" counter** on the tool or container (shovel, bucket, pan, with `DirtLoads` and `DirtQualityAverage`).
- **Physics "dirt chunk" actors** (`BP_DirtResource`), which have mass, size and quality and are made when dirt is dumped where it can't rejoin terrain.

Dirt does not flow or avalanche. Water is **scripted rather than simulated**: static water volumes, pipe networks that propagate a numeric pressure, and spawned water projectile actors used as visuals and triggers.

### Inferences
- [INFERENCE] There is no fluid simulation anywhere. Water is (1) static volumes acting as boolean triggers, (2) a graph-propagated scalar (pressure) through pipes, and (3) cosmetic or trigger projectile meshes at outlets. - [INFERENCE] Dirt is effectively conserved as numeric loads with an average quality, and becomes a physical body only when dumped onto a non-voxel surface. A good web design: tools and containers hold integers, and physics chunks merge into containers on overlap.

### Gaps
- There is no confirmation of whether dirt chunks merge with each other. The exact mass per load and the panning loot formula are not public, as `GenerateGems`/`SpawnResource` internals are unknown.

## 4. Picking up, carrying, throwing, stacking; machine connections

### Takeaway
Carrying is **not** a physics-handle drag. The item is lerped into a hand or build socket and attached, with collision switched to a "Held" profile and a first-person proxy mesh. Dropping is validated by a collision scan. Placement of buildables uses a ghost "placing" mode with XYZ rotation, distance scroll and (since 3.0) snapping. Conveyors move items kinematically. Machine connections are socket/hook attachments, not physics joints.

### Takeaway

### Inferences
- [INFERENCE] For a browser game with optional co-op: make the host authoritative. Sleeping or locked bodies cost zero bandwidth (the measured idle world had no simulating bodies), so only "awake" items need streaming. Terrain sync works best as replicated *edit operations* (sphere add/remove with a sequence number), which is what coopnet does, rather than replicated voxel data.
- [INFERENCE] Save as an entity list (class id, transform, a few properties) plus per-dig-site compressed voxel diffs, with rolling backups. Offer "don't save loose dirt/ore" and "clear loose items" options, as Hydroneer does.

### Gaps
- The exact Workshop packaging format (pak naming, mount order) was not documented in the sources read. No official first-party modkit from the developer was found; all kits are community-made.

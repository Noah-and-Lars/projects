Why it happens & how to fix it

The bug is not the quote character — it's that user input is concatenated into SQL as code. The fix is to make input always data, using parameterized (bound) queries:

// ❌ vulnerable (what this lab does)
const q = `SELECT ... WHERE username = '${username}' AND password = '${password}'`;

// ✅ fixed — Cloudflare D1 / most drivers
await env.DB
  .prepare('SELECT id, username, role FROM users WHERE username = ? AND password = ?')
  .bind(username, password)
  .all();

Also: hash passwords (bcrypt/scrypt/argon2) instead of storing plaintext, give the DB user least-privilege, and don't return raw DB errors to clients. Parameterization is the one that actually closes the injection.
